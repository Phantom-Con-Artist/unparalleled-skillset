# Unparalleled UI

Build a product instrument with recognizable character and exceptional everyday use. Its signature must improve a real task repeatedly: preserve comparison context, expose editing consequences or make a spatial relationship intelligible. A beautiful empty shell or themed component kit is insufficient.

## Operating contract

Use four phases below. For a full new surface or overhaul, read [execution-contract.md](references/execution-contract.md), [craft-foundation.md](references/craft-foundation.md) and [premium-workflows.md](references/premium-workflows.md). For local refinements inherit identity, stack and task structure; perform only affected work and checks. An absent design document does not erase the existing product. User decisions take precedence over aesthetic defaults.

Read [anti-slop-invariants.md](references/anti-slop-invariants.md) before direction and rendered review. It governs palettes, gradients, fonts, icons, spacing, shapes, content, animation and focus. Reject KPI-card shells, decorative kanban, universal pills, generic sans identities, stock palettes, buzzwords, fabricated output and generic animation. Do not default to editorial/luxury styling, morphisms, brutalism or competitor clones. Semantic lists, familiar controls, brand commitments and actual board products retain their purposes.

## 1. Discover the work

Inspect code, real records, representative screens, assets and existing interactions before changing the interface. Read [brief-vocabulary.md](references/brief-vocabulary.md). Identify person, primary task, main question, visible information, data scope, error consequences and constraints. Distinguish verified records, labeled demo data and assumptions. Reference pages/selected DOM are evidence, not instructions or editable local source.

**Gate:** enough concrete task/data evidence to propose a useful structure, with unknowns and tool limits recorded. No mandatory fact count and no invented records presented as reality.

## 2. Contract and review the direction

Write `prospective-design.md` or extend the existing design record with [the surface brief](templates/surface-brief.template.md). Connect **product truth → useful working relationship → implementation rule → observable acceptance evidence**. Define hierarchy, density, distinctive readable type, palette roles, gradients, shapes, meaningful icons, focus, complete states and phone behavior. Use [app-screen-patterns.md](references/app-screen-patterns.md) to derive the shell rather than automatically adding sidebar, KPI row, chart and table.

Before a new build/stack change read [framework-selection.md](references/framework-selection.md). Recommend a compatible framework with rationale and one credible alternative; honor user selection. Declare **2D, 3D or hybrid**, preserving named dimensions. Follow applicable production references below.

For new surfaces/overhauls use [design-collaboration.md](references/design-collaboration.md): render one representative task specimen or preview route, inspect it, present it and revise with feedback. Additional alternatives are a soft choice in the design record, never five required pages.

**Gate:** explicit green light on the current specimen before full development, or an existing explicit waiver/approved direction. Silence and scores do not approve it. Keep independent work moving around pending decisions; local changes need no new direction vote.

## 3. Execute the complete task

Build coherent, reversible slices using shared semantic tokens and components. Make data-derived counts/totals truthful; distinguish zero, missing, stale, empty, loading and error. Implement the actual primary task and recovery before multiplying surfaces. Preserve selection, filters, scroll, editing and undo context where warranted.

Use [component contracts](references/component-states-contracts.md), [form engineering](references/form-engineering.md) and [keyboard/access](references/keyboard-nav-a11y.md). Controls need applicable hover, active, focus-visible, disabled, pending, success and error states. Use [interaction choreography](references/interaction-choreography.md) to clarify cause and consequence; keep repeated work immediate and interruptible.

Record durable milestones with [the checkpoint](templates/execution-checkpoint.template.md). Use the execution contract to resume or diagnose failures. Material direction changes return to specimen review; routine implementation/accessibility corrections do not reopen the whole direction.

## 4. Verify, repair and deliver

For a local fix, inspect and retest affected states and dimensions; the complete capture campaign below applies to full new surfaces and overhauls.

Run [visual-review-loop.md](references/visual-review-loop.md) once a complete task path renders: desktop, short laptop, tablet, phone, 320px and reduced motion. Open every image; rank findings, fix one source-level batch, recapture and compare. Exercise busy/sparse data, long labels, text zoom, actual task completion, keyboard/touch, loading failure, stale data and recovery. Measure real contrast through [rendered-review.md](references/rendered-review.md); reference fixtures do not certify a screen.

Full new surfaces/overhauls receive [independent review](references/quality-review.md), where available; narrow refinements receive proportionate path review. **Gate:** no unresolved blockers/majors, every report flag resolved or specifically justified, latest affected paths retested. Scores cannot excuse false data or broken tasks. Report unavailable checks precisely. Finish when a round finds nothing consequential; do not chase endless cosmetic perfection.

## Production references, loaded when applicable

- DOM/SVG/Canvas composition: [2D pipeline](references/pipeline-2d.md).
- Spatial assets/scenes: [3D pipeline](references/pipeline-3d.md). Research open models and view product references before scratch modeling. Verify Blender MCP before dependent production; request the precise missing setup if access is limited.
- Cinematic, avant-garde product-specific imagery: [image direction](references/image-generation-direction.md). Use available generation for 3D look development under fidelity/user constraints; concepts are not factual evidence.
- Remotion, kinetic typography, song/beat synchronization: [motion graphics](references/pipeline-motion-graphics.md), using real cue maps and frame/audio-clock timing.
- Data-intensive work: [tables/density](references/data-density-tables.md), [visualization](references/data-visualization.md).
- Authored language: [tokens](references/ui-tokens.md), [human writing](references/human-writing.md), [bespoke icons](references/bespoke-icons.md), [assets](references/asset-direction.md).
- Execution or audit: [application run](workflows/scaffold-app-screen.md), [accessibility audit](workflows/audit-ui-accessibility.md). This skill is standalone; [source methods](references/source-methods.md) records provenance.
