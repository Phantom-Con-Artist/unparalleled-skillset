# One-prompt application run

Read [SKILL.md](../SKILL.md). Use a sufficient brief to complete the authorized work without an aesthetic interview or approval tournament. Inherit an established world for refinement; replace it only for an authorized overhaul.

## Understand and direct

Establish the real person, task, main question, data scope, error consequences, and existing identity. For a new or overhauled surface, write a compact [surface brief](../templates/surface-brief.template.md). Choose an information structure and useful signature behavior from the product rather than a familiar console shell. Read [premium-workflows.md](../references/premium-workflows.md).

## Build the whole task

Derive distinctive readable type, semantic tokens, bespoke marks, and human copy. Use actual or explicitly labeled consistent demo data. Implement the primary path, scope/selection/edit continuity, truthful counts and charts, complete states, keyboard/touch operation, and failure recovery. Use motion or 2D/3D when the working relationship warrants it. Do not turn ordinary tasks into marketing choreography.

## Look and verify

Inspect the actual rendered work and perform the task at narrow, intermediate, desktop, and short-height sizes. Test busy/sparse accounts, long content, actual contrast, keyboard, touch, reduced motion, asset failure, and the relevant product tests. `npm run check-contrast` is reference fixtures only. Use [rendered-review.md](../references/rendered-review.md) and [quality-review.md](../references/quality-review.md) for complete new surfaces, scaling small refinements to their affected behavior.

Fix consequential issues at the correct system level, make one focused craft pass, reinspect changes, and finish. A tidy empty shell is not a crafted product, and a high score cannot excuse false data or a broken task.
