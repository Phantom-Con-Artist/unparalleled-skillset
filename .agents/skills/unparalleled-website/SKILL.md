# Unparalleled Website

Build an authored experience whose premise, assets, behavior and complete journey belong to this product. Recommend an experimental relationship in composition, narrative or interaction. Removing cards and adding oversized type, whitespace and fine rules is an editorial fallback, not a governing idea.

## Operating contract

Use four phases below. For a new direction or overhaul, read [execution-contract.md](references/execution-contract.md), [craft-foundation.md](references/craft-foundation.md) and [experimental-direction.md](references/experimental-direction.md). For a local fix, inherit the existing identity and stack; perform only affected work and checks. Existing user decisions take precedence over aesthetic defaults. No fixed fact quota, page quota, genre tournament or extra approval for an approved direction.

Read [anti-slop-invariants.md](references/anti-slop-invariants.md) before direction and rendered review. It governs palettes, gradients, fonts, icons, spacing, shapes, content, animation and focus. Reject template cards/pills, generic sans identities, stock palettes, buzzwords, invented proof, decorative icon inventories and generic animation. Do not substitute editorial/luxury, brutalism, morphisms or another genre recipe. Defaults never override explicit brand/user choices, accessible semantics or familiar control meanings.

## 1. Discover the subject

Inspect code, real content, assets, existing behavior and supplied references before changing the experience. Read [brief-vocabulary.md](references/brief-vocabulary.md). Identify audience, primary action, distinctive mechanism, product evidence and constraints. Research competitors/references with available permitted tools; distinguish live observation, screenshot, creator account and inference. Do not invent findings when access fails.

**Gate:** enough verified subject truth to support a particular premise, plus visible assumptions and capability gaps. Sparse evidence narrows the proposal; it never licenses fictional claims.

## 2. Contract and review the direction

Write or update `prospective-design.md` with [the template](templates/prospective-design.template.md). Connect **product truth → experiment → implementation rule → observable acceptance evidence**. Define first frame, full journey, real content, palette roles, actual type, gradients, focus, spacing, shapes, authored assets and signature behavior. Derive an evidence-based [vocabulary](references/vocabulary-generator.md), aiming for 15–25 useful terms when supported. State why a competitor-name swap breaks the premise.

Before a new build/stack change, use [framework-selection.md](references/framework-selection.md): recommend a compatible framework with rationale and one credible alternative; honor the user's selection. Declare **2D, 3D or hybrid**, preserving a named dimension. Follow the applicable production references below.

Use [design-collaboration.md](references/design-collaboration.md) to render one representative HTML specimen or preview route with real content, a later action segment and the decisive interaction. Inspect it before presenting. Extra alternatives are a soft choice in the prospective record. Revise with feedback.

**Gate:** explicit green light on the current specimen before full development, or an existing explicit review waiver/approved direction. Silence and scores do not approve a specimen. Continue independent work while a consequential decision is pending.

## 3. Execute the approved experience

Build coherent, reversible slices; prototype the hardest relationship early. Carry the approved premise through navigation, secondary content, forms, actions, return and failure states. Use [experience-engineering.md](references/experience-engineering.md) for lifecycle and fallbacks. Preserve native scrolling, semantic content, keyboard/touch use, reduced motion and a complete static reading path. Inspect the first complete path before multiplying sections.

Record durable milestones using [the checkpoint](templates/execution-checkpoint.template.md); use the execution contract to resume or diagnose failures. A material direction change returns to specimen review. Routine implementation and accessibility corrections do not reopen the entire direction.

## 4. Verify, repair and deliver

For a local fix, inspect and retest affected states and dimensions; the complete capture campaign below applies to full new surfaces and overhauls.

Run [visual-review-loop.md](references/visual-review-loop.md): desktop, short laptop, tablet, phone, 320px and reduced motion; open every capture, rank findings, fix one source-level batch, recapture and compare. Test actual actions, input, scroll reversal, asset failure and content extremes. Use [rendered-review.md](references/rendered-review.md) for measured contrast and behavior. Fixture checks cannot certify a screen.

For full new experiences/overhauls obtain [independent review](references/subagent-review-rubric.md), where available. **Gate:** no unresolved blockers/majors; every report flag resolved, evidenced as false positive or justified by an explicit requirement; latest affected paths retested. Scores cannot waive failures. If a tool is unavailable, report the unverified part rather than claiming completion. Finish when a review round finds nothing consequential; no endless cosmetic loop.
