# Unparalleled Agent Workspace Guidelines

This repository contains two independently installable design skills. Read the applicable complete skill before designing or changing generated work.

## Application UI

Use `.agents/skills/unparalleled-ui/SKILL.md` for software people work in: dashboards, tables, forms, settings, and component systems. Prioritize a product-specific direction, the real task, semantic tokens, complete interaction and data states, truthful data, keyboard navigation, readable density, and actual WCAG AA contrast. Read the shared craft foundation and premium workflow references for full new surfaces or overhauls.

## Public websites

Use `.agents/skills/unparalleled-website/SKILL.md` for public pages and product stories. Follow its four-phase runbook with an experimental, product-specific recommendation: discover the subject; contract the direction in `prospective-design.md` and review one live specimen; execute the approved experience; verify, repair and independently review. Evidence-based vocabulary, authored assets and concrete design choices remain part of the contract. Multiple directions are a soft choice in the prospective record; there is no five-page/specimen quota. For full new surfaces/overhauls, revise with the user until explicit green light before full development, unless the user already explicitly waived review or approved the direction. Local fixes inherit the established identity. Read `references/experimental-direction.md`; do not default to oversized type, neutral palettes, fine rules and spacious editorial prose spreads. Use `references/website-3d-references.md` for Igloo and the user-supplied Algal Biotech Lab demo, respecting their inspection limits.

## Frameworks and production pipelines

Both skills require context-based framework/runtime recommendations before new builds, with one credible alternative and explicit user choice taking precedence. Technical recommendations do not waive a required specimen approval gate. Retain the stack for local refinements. Read the applicable skill's `references/framework-selection.md`; declare 2D, 3D or hybrid and follow its corresponding pipeline. For scratch models, research open models and inspect product visual references first. Configure and verify Blender with MCP for Blender before dependent 3D production, or request the exact inaccessible setup step while continuing independent work. Use available image-generation capabilities for cinematic, product-specific, avant-garde 3D look development subject to explicit user/fidelity/tool constraints. Read `references/pipeline-motion-graphics.md` for Remotion, kinetic text, song beat/phrase mapping, audio synchronization and rendered video. Record decisions and evidence in the existing direction contract.

## Authored experience

Both skills blend selected methods from Impeccable, Awwwards, and Taste into standalone guidance. They include a sourced interpretation of the nine supplied reference sites, distinguishing live observations from creator accounts and incomplete scene inspection. Use a direction contract to connect product truth, governing idea, visual grammar, authored assets, signature behavior, complete journey, and acceptance evidence. Premium means conviction and care across the actual product, not a stock luxury aesthetic. Prototype the decisive interaction early and carry the identity beyond the first screen.

## Shared craft contract

Generated interfaces and copy must avoid emoji decoration, visible bullet-point marketing inventories, stock icon tiles, buzzword filler, formulaic slogans, em-dash spam, generic sans-serif visual identities, stock palettes, and mainstream design genre recipes. Use meaningful bespoke SVG icons, distinctive readable type, honest human writing, and colors derived from the product. Semantic lists and established control meanings remain available for accessibility. Explicit user choices and existing brand requirements take precedence.

Card grids, kanban lanes, and pill-shaped buttons, badges, chips, and filters are banned by default, as are generic SaaS color (indigo buttons, purple-blue gradients, cyan or emerald "live" accents on slate) and neon aesthetics unless the user asks. Each skill's `references/generic-tells.md` dissects a real generic page. Read brief words with `references/brief-vocabulary.md`: "bespoke" and "handcrafted" mean precise product-specific craft, never handwriting fonts or sketch textures; "handmade", "handwritten", and "hand-drawn" ask for literal hand marks. A named 2D or 3D dimension is a constraint.

Do not prescribe glassmorphism, neumorphism, skeuomorphism, claymorphism or another named morphism, editorial/luxury spreads, Swiss posters, brutalism, bento-first SaaS, or Linear/Vercel clones. Grids, serif type, shadows, and perspective remain tools; invent their relationship from the product rather than selecting a genre.

For websites, blend 2D and 3D through meaningful interactivity, motion graphics, and scroll-driven storytelling in proportion to the brief. Preserve native scrolling, keyboard and touch use, reduced motion, and a complete static reading path. No compulsory grain, glow, tilt, particles, or heavy 3D engine.

Allow deliberate, discreet irregularity when it gives the work character. Keep facts, access, readable contrast, and controls correct. Fix findings at their source, recapture and compare against the approved specimen; finish when no blockers/majors remain and checks hold together. Do not chase endless cosmetic perfection or waive unresolved defects with a score.

## Visual review loop

Agents must see what they build. Each skill's `references/visual-review-loop.md` defines the loop: confirm a browser (a connected Playwright MCP tool, or `node scripts/capture.mjs`, which installs Playwright and Chromium into `~/.cache/unparalleled/playwright` with `--install`), capture desktop, short laptop, tablet, phone, and 320px views plus reduced motion, open every screenshot, fix one ranked batch at its source, recapture, and compare. Keep a severity/evidence/remedy/retest ledger and compare matched states against the approved specimen. Every report flag is fixed/retested, evidenced as a false positive, or tied to an explicit user/brand requirement with functional/access checks. Specimen review continues to user green light or explicit waiver; production review ends when no blockers/majors remain and actual acceptance checks pass.

## Validation

Run `npm run validate-all` for skill structure and local Markdown links. Run `npm run check-contrast` for reference fixtures only. Neither proves design quality or rendered accessibility. Validate actual measured pairs with each skill's `scripts/check-contrast.mjs --pairs <pairs.json>` and inspect the rendered work. Token generation requires project-specific `--input <tokens.json> --output <tokens.css>` and supplies no palette or font preset.

## Stronger design defaults

Read each skill's `references/anti-slop-invariants.md` for palettes/gradients, buzzwords and unsupported copy, interchangeable fonts, stock icon identity, universal spacing, generic shapes, focus and formulaic motion. Consistent scales, native controls, explicit brands and accessible fallbacks remain valid; replacing a template with an empty or editorial page is not a solution. New/overhauled application surfaces use a representative task specimen and the same user-review contract; ordinary local fixes preserve scope.

## Long-task execution

Both skills use concise entrypoints, just-in-time references and an evidence-led execution contract. For new surfaces/overhauls or long work read the applicable `references/execution-contract.md`. Connect subject truth to implementation rules and observable acceptance evidence. Save durable milestone checkpoints in the existing design record; on resume verify source and current revision before continuing. Diagnose failures before retrying. Script success alone never proves visual quality, user approval or completion. Local refinements use proportional checks and retain existing identity.
